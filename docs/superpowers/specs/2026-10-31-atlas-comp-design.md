# Atlas Comp: a generative compositing app on ComfyUI

Design, 2026-10-31. Proposed by Claude, approved by Mike ("I like your idea let's do it").

## Intent

atlas-vfx already does the hard parts as ComfyUI nodes:
- a tracked plate;
- camera-locked layers;
- LTX passes (relight, alpha matte, clean loop);
- delivery to Nuke.

Using them still means building and reading node graphs. Atlas Comp puts a compositor's screen in front: viewer,
layer stack, inspector and timeline. The artist (a Nuke, After Effects or Photoshop user, not a ComfyUI expert)
works on layers with generative operations as buttons, while ComfyUI runs the work in the background. Mike's words:
"a new type of generative compositing application solely built to be based on comfy but wrapped into a UI".

## Goals

- **One screen per shot.**
  - Viewer: OCIO view, A/B wipe, f-stops, zoom, false colour.
  - Layer stack: visibility, solo, opacity, blend.
  - Inspector: the selected layer's recipe in artist terms.
  - Timeline: Nuke frames, a scrubber, and per-layer render state.
- **Generative operations as recipes.** A recipe is a ComfyUI graph plus a JSON that maps UI fields to graph inputs.
  New recipes need no Python.
- **Preview first.**
  - Preview runs a recipe on a few frames at reduced size, with the tiny VAE, and streams live sampler previews into
    the viewer.
  - Render runs the full job, streamed to disk.
- **Disk is the truth.**
  - A shot is a folder: `shot.json`, `layers/<layer>/vNNN/` EXRs with sidecars.
  - The app rebuilds its state from disk.
  - Every render is a version that can be compared.
- **Ways out:**
  - Nuke script (the existing Nuke Builder);
  - "Open in ComfyUI" for any recipe's graph.

## Non-goals

- A full compositor: Nuke stays the finishing tool.
- Roto or keying tools: mattes come from Alpha-Gen.
- Cloud or multi-user.
- A frontend build chain.

## Anti-goals (failure even if it works)

- Files the artist cannot find.
- Lossy colour anywhere in the pipe: ACEScg EXR on disk, OCIO-named view for display.
- A UI that freezes while the GPU works.
- A second source of truth that drifts from disk.

## Constraints (from the repo rules)

- **No new dependencies.**
  - Server: aiohttp (ComfyUI's own), numpy, OpenCV, OCIO, OIIO.
  - Browser: plain ES modules, plus three.js already vendored for the sun globe.
- **Widgets and HTTP inputs are untrusted.** ComfyUI's API has no auth.
  - Every path goes through `plate.clean_path` / `resolve_out_dir` / `safe_name`.
  - Every read is confined to the work root (and the plate the shot names).
  - Recipe fields are validated against the recipe's schema; nothing is executed.
- **Placement and import graph:**
  - The app's browser files live in `app/`, not `web/`: ComfyUI loads every `.js` under `web/` into its graph editor.
  - Server code lives in a new package `atlas_vfx/comp/`. It may import every package (like `deliver/`); nothing
    imports it. The import graph changes, so `AGENTS.md`, `CLAUDE.md` and `tests/test_import.py` `ALLOWED` change in
    the same commit.
- No usernames in shipped files, and tests for everything, as now.

## The how, as decided

- **Served by ComfyUI itself.**
  - The pack registers aiohttp routes on `PromptServer.instance`.
  - The app opens at `http://127.0.0.1:8188/atlas`.
  - Same install, same port.
- **Queueing:**
  - The browser asks our server for a filled, validated API graph, then queues it with ComfyUI's own `/prompt`
    under its `client_id`.
  - Live previews and progress come back on ComfyUI's websocket.
- **Recipes:**
  - `recipes/<name>.json`: label, the API graph (generated by the existing tools/*_workflow.py builders), fields
    (label, type, default, choices, the node input each sets), and the preview overrides (length, size, tiny VAE
    decode).
  - Phase 1 recipes:
    - Matte: Alpha-Gen.
    - Relight: LTX-2.3 Relight with mirror, then Relight Transfer Files.
    - Sky: Physical Sky.
- **Viewer frames are composited on the server.**
  - The visible stack is composited in linear ACEScg (over, plus, multiply, screen, opacity) and sent as a display
    JPEG through the chosen OCIO view.
  - It reuses the Viewer node's code.
  - Claude's call: this changes the earlier "browser composites" proposal. It is simpler, colour-exact and fewer
    bytes. Browser-side compositing can come later if scrubbing needs it.
- **Versions:** each render writes `layers/<layer>/vNNN/` and the layer points at a chosen version. A/B compares any
  two versions or layers.

## Desktop app (decided 2026-10-31, after the first draft)

Mike: "Let's scope a comfy fork wrapped into an electron or rust app", "we may need advanced user graph dive in
options", "think higgsfield but better", "Tauri sounds good, we should probably include atlas camera".

- **Shell: Tauri.** It uses the Rust backend and Windows' own WebView2. The window loads the same web UI (`/atlas`)
  described above, so the browser app stays the core.
- **Engine: no fork of ComfyUI** (Claude's recommendation; Mike chose Tauri on that basis).
  - The app ships a pinned, unmodified ComfyUI with atlas-vfx and Atlas Camera.
  - It runs ComfyUI as a child process that the shell starts, watches and restarts, and the shell owns the launch
    flags. That avoids, for example, `--enable-triton-backend`, which breaks the LTX VAE decode.
  - ComfyUI is GPL-3: bundling it unmodified as a separate process keeps the shell and packs MIT. The licence text
    and a source offer ship with the app, recorded in `atlas_components.json` before any release.
- **Graph dive-in.**
  - Every recipe layer has "Open graph": ComfyUI's own editor, from the same process, opens in a panel or tab with
    that layer's filled graph.
  - An edited graph saves back as a custom recipe (the same JSON, plus the edited graph), so a technical director
    can make new buttons for artists.
  - Two levels, one engine.
- **Atlas Camera included.**
  - It is the shot's front door: a still photograph gives a metric camera and projection geometry (Atlas Input). A
    plate gives a tracked or imported camera (atlas-vfx camera_side today, moving into Atlas Camera at the split).
  - The app bundles the released Atlas Camera pack as is, through its own nodes, routes and viewport.
  - The dev tree `Desktop/AtlasCamera_Claude` is never edited from this work. Anything missing goes to
    `docs/dev/UPSTREAM_TODO.md`.
- **Atlas Scene included: one Tauri app, three rooms** (Mike: "And atlas scene then"; chose "one Tauri app, three
  rooms").
  - The rooms share one scene, the `.atlas` package that Atlas Camera already writes and Atlas Scene owns
    (`docs/atlas_scene/ATLAS_SCENE_PRODUCER_SPEC.md` in Atlas Scene):
    - **Camera:** a photograph or plate becomes a camera and geometry.
    - **Scene:** inspect, place and repair in 3D; sky and sun.
    - **Comp:** layers, recipes, viewer, Nuke out.
  - The Tauri shell runs two engines as child processes: ComfyUI with atlas-vfx and Atlas Camera, and the Atlas
    Scene service (FastAPI, localhost:8765).
  - Atlas Scene's web viewport (PlayCanvas, built with Vite in its own repo) loads in the Scene room.
  - Atlas Scene's Electron shell retires for users and may stay for its own development.
  - **Atlas Scene state, 2026-10-31:** a v0.1 slice. Its model, `.atlas` round trip, operations API with undo, the
    service and a viewport that orbits and picks work. GLB loading, camera backplate, gizmos and MCP are not built
    yet.
  - Changes needed in Atlas Scene or Atlas Camera are made in their own repos, never from this one; this repo records
    them in `docs/dev/UPSTREAM_TODO.md`.
- **"Higgsfield but better."**
  - Keep the ease: a gallery of presets with result thumbnails, one click to run, a feed of what came back.
  - Add what a preset app cannot:
    - the artist's real plate and camera;
    - camera-locked layers;
    - ACEScg EXRs and Nuke out;
    - local GPUs with no credits;
    - versions to wipe between;
    - the graph always one click away.

## Phases

1. **Viewer and recipes:**
   - shot create/open from a plate + range + camera;
   - layer stack over existing outputs (add any EXR sequence as a layer);
   - viewer with A/B and f-stops;
   - Matte, Relight and Sky recipes with Preview and Render;
   - live previews.
1.5. **Desktop and dive-in:**
   - the Tauri shell (ComfyUI child process with our flags, a status bar for GPU, queue and engine, native file
     pickers);
   - "Open graph" and save as a custom recipe;
   - the preset gallery with thumbnails;
   - shot from a photograph through Atlas Camera;
   - the Scene room: Atlas Scene's service and viewport in the shell, with the shot's `.atlas` opened from Comp.
2. **Versions and delivery:**
   - versions and A/B between them;
   - chunked long shots on the timeline;
   - Nuke out;
   - "Open in ComfyUI".
3. **More recipes:** Insert Element (clean loop), Clean Plate, and camera solve and plate setup in the UI.
